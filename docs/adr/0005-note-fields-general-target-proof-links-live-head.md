# Separate note fields, general Target, proof links as Evidence, live-head.json written by the skill

An Annotation (a note) now has separate fields: `verdict`, `severity`, `source` and `suggestion`. The text in `summary` stays markdown. The verdict says if the behaviour is what was asked for. The suggestion says what to change. The Review Document gets `schemaVersion` 2 for this. The engine checks `verdict` for every note in a version 2 document. It checks `suggestion` when the verdict is `wrong` or `missing`. A missing field gives a Diagnostic (`missing-verdict`, `missing-suggestion`). It does not block the bundle. A version 1 document gets no check for these fields, so old bundles stay readable and open without new Diagnostics. We chose the version number as the one switch. It is the smallest rule: no field-by-field guessing and no migration step.

A finding with no code line uses a general Target, `{ type: 'general' }`. It points at the whole Comparison. Only an Annotation may use it. A Behavioral Group, a related Target and a Comment still need a code Target. The renderer puts general notes in their own list. It counts them in "open gaps" unless the verdict is `intended`. A later round does not carry them forward, because they describe one head.

A proof link is an Evidence item, not a new schema type. Its `targetIds` name a code Target (an Annotation id or a changed file path) and an image Target (the path of a changed image in the patch). The validator gives `invalid-proof-link` when either one does not exist. The renderer lists each proof on the file or hunk it proves. It also lists the code on the image, so the UI can link both ways. We reused Evidence because it already holds an image, a caption and a kind.

`live-head.json` is a new optional file in the bundle: `{ head, checkedAt }`. The skill writes it when it opens or updates a bundle, because only the skill may use the network ([ADR 0003](0003-run-locally-and-offline.md)). The engine only reads it. The server shows it with a stale flag and the round number. The bundle stays immutable ([ADR 0002](0002-use-immutable-bundles-with-separated-ownership.md)). The file records what the forge said at one time. It is not part of the Comparison.

Intent also gets an optional `visuals` list. The engine checks that each image path exists under `assets/`. The limit of 3 images shown is a UI rule, not a schema rule.
