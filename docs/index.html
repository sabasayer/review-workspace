A decision surface for reviewing code — not another AI summary

Review Workspace turns a flat diff into an evidence-linked map of intent, behavior, risk, and observable effects — so a reviewer reaches a decision faster, without losing the code itself under a wall of generated prose.

Get started View source

01What it is

A local, offline tool for reviewing one Comparison — an MR, a PR, or any base/head pair. A separate Generator (a Claude Code skill) reads the diff plus whatever evidence exists (CI results, screenshots, the MR description) and writes a structured Review Document: files clustered into behavioral groups, annotations pinned to exact lines, evidence classified as observed fact vs. author claim vs. inference, and open questions. You review it in a local web UI — side-by-side or inline diff, full-screen image compare for screenshot diffs, and threaded questions on any line.

The Generator never decides approve/request-changes. That stays yours.

02How it flows

MR / PRThe Comparison under review, plus its description, discussions, and CI results.
→
GeneratorClaude Code skill reads the patch + evidence, writes a Review Document.
→

→
Local UIServed on loopback — you read, ask questions, and decide.

03Core concepts

Review Bundle
The complete portable resource for reviewing one Comparison — code evidence, interpretation, assets, questions, and reviewer state.
Comparison
The exact base and head revisions whose differences are under review.
Review Document
The semantic interpretation of a Comparison, produced and updated by a Generator.
Generator
Anything capable of producing or updating a valid Review Document — here, a Claude Code skill.
Behavioral Group
An ordered cluster of related changes that together implement or verify one behavior.
Annotation
A concise interpretation attached to a specific file, hunk, line, or binary Target, backed by evidence.
Evidence
An attributable observation — classified as observed fact, author claim, or inference. Never presented as more certain than it is.
Question / Answer
A Reviewer's request for clarification on any Target, and the Generator's one-per-Question response.
Diagnostic
A visible problem found validating a bundle — a stale line reference, a missing asset — surfaced, never silently dropped.

04What it won't do

  • Never decides for you. No approve/request-changes button driven by the Generator — that stays a human call.
  • Never hides the diff. Every changed file is reachable through the Review Document; summaries orient, they don't replace the code.
  • Never blurs fact and guess. Every piece of evidence is labeled observed, author-claimed, or inferred.
  • Never phones home. Runs entirely on loopback, against your own bundle directory — nothing leaves your machine.

05Quick start

Requires Claude Code (CLI, desktop app, or claude.ai/code) and Node ≥24. A plain claude.ai chat can't run this — the skill shells out to glab/gh/npx.

1. Install the skill (one time):

npx skills add sabasayer/review-workspace --global --agent claude-code -y

2. Ask Claude Code to review something:

Review this MR using the review-workspace skill: <paste MR/PR URL>

It scaffolds a bundle, generates the Review Document, and serves the UI at a printed localhost URL.

Already have a bundle? Serve it directly:

npx review-workspace serve .bundles/<name> --port 4317
